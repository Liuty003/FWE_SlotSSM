# 1. 目前结构的问题具体在哪里

你现在是：

```text
RGB / wrist RGB
        │
        ▼
SlotAttention
        │
        ▼
SlotSSM ───────► Gate
                   │
                   ▼
            Candidate Verifier
                   │
                   ▼
            Recovery Adapter
                   │
                   ▼
                 Action
```

问题是中间其实缺了一条：

```text
Action ─────────────► Slot / object state change
```

训练 recovery adapter 时，如果只是：

[
\mathcal L_{\text{act}}
=======================

|\hat A-A^*|
]

那么网络完全可能学成：

```text
instruction
+ proprio
+ mode
       ↓
recovery action
```

SlotSSM 虽然接进去了，网络可以直接忽略。

这也是很多“object-centric policy”容易遇到的问题：**有 object representation，不等于 policy 真正在 object representation 上做控制。**

SlotVLA至少已经把 task-relevant object slots 和 relation tokens 直接作为 action decoder 的输入，并且专门建模 gripper-object / object-object relation；STORM则进一步强调需要把 object-centric representation 和 downstream policy 联合适配，否则视觉 slot 不一定天然具有 manipulation 所需要的 task semantics。([arXiv][1])

# 2. 我认为最重要的改动：让 SlotSSM 变成 Action-Conditioned SlotSSM

你现在 SlotSSM 大概可以理解成：

[
S_t = f_{\text{SSM}}(S_{t-1},V_t)
]

也就是：

> 上一时刻物体状态 + 当前视觉
> → 当前物体状态。

但机器人环境其实应该是：

[
\boxed{
S_t=f_{\text{SSM}}
(S_{t-1},V_t,a_{t-1},p_{t-1})
}
]

其中：

* (S_t={s_t^1,\cdots,s_t^K})：当前 object slots；
* (V_t)：当前视觉；
* (a_{t-1})：机器人刚执行的动作；
* (p_{t-1})：proprio。

这样 SlotSSM 学到的是：

> **机器人刚才做了这个动作以后，各个物体发生了什么变化。**

原始 Embodied-SlotSSM 的 SSM 主要根据每个视觉 slot 更新对应的 temporal hidden state，然后用这些 object-memory states 条件化 action prediction；它本身并没有强制建模 action 对 object slot 的因果影响。([arxiv.org][2])

而你恰恰可以在这里做出区别。

---

# 3. 更关键的是加一个 Slot Transition Model

这是我目前最推荐的桥梁。

假设当前：

[
S_t={s_t^1,\ldots,s_t^K}
]

机器人准备执行：

[
A_t=[a_t,\ldots,a_{t+7}]
]

增加一个很小的 dynamics head：

[
\boxed{
\hat S_{t+H}=F_\phi(S_t,A_t,p_t)
}
]

它的含义非常直接：

> **如果当前场景状态是 (S_t)，然后机器人执行这 8 步动作，物体应该变成什么状态？**

训练时你其实天然有监督：

```text
frame t
   ↓ SlotAttention
S_t

action t:t+7
   ↓

frame t+8
   ↓ SlotAttention
S_{t+8}
```

于是：

[
\mathcal L_{\text{dyn}}
=======================

|\hat S_{t+8}-\operatorname{sg}(S_{t+8})|
]

其中 `sg` 是 stop-gradient，避免 Slot encoder 为了迎合 dynamics loss 自己乱漂。

这样就真正建立了：

[
\boxed{
Action
\longleftrightarrow
Object-state change
}
]

OA-WAM 最近采用的思路和这个非常接近：它同时训练 action head 与 per-object future-state prediction head，用下一时刻 slot content / pose 作为 world-model supervision，使动作生成和对象状态演化共享同一个表示空间。([arXiv][3])

# 4. 然后你的 failure detection 也会突然变得很合理

这个设计最漂亮的地方其实不只是 action generation。

假设上一时刻：

[
S_{t-1}
]

机器人执行了：

[
a_{t-1}
]

你的 dynamics model 预测：

[
\hat S_t
========

F(S_{t-1},a_{t-1})
]

然后真实视觉进来以后，SlotSSM得到：

[
S_t
]

那么直接算：

[
\boxed{
E_t=R(S_t,\hat S_t)
}
]

这个 (E_t) 就是：

> **Expected outcome 和 Observed outcome 的差异。**

例如抓书。

正常情况下：

```text
动作：
gripper close + lift

模型预计：
book slot 跟着 gripper 向上移动
```

结果真实观测：

```text
book slot 基本没动
gripper 已经向上
```

于是：

[
\hat s_t^{book}\neq s_t^{book}
]

这就是非常自然的 **grasp failure**。

所以 neural gate 不再莫名其妙地：

[
g_t=G(S_t)
]

而是：

[
\boxed{
g_t
===

G(S_t,\hat S_t,E_t,p_t,L)
}
]

从论文故事上就顺很多：

```text
过去状态
   +
执行动作
   ↓
预测应该发生什么
   ↓
观察实际发生什么
   ↓
expected vs observed mismatch
   ↓
Failure
```

这比“SlotSSM feature → 一个 MLP 判断失败”强很多。

# 5. Recovery action 也应该围绕这个 Error State 来生成

现在最核心的变量就不再是单纯 (S_t)。

而是：

[
\boxed{
Z_t=
[S_t,E_t,p_t,L]
}
]

更进一步，我甚至不建议直接把 16 个 slots 全 concat。

应该先得到几个 **control-relevant roles**：

[
s_t^{target}
]

目标物，例如 book；

[
s_t^{reference}
]

例如 bookshelf / plate / basket；

以及：

[
s_t^{robot}=MLP(p_t)
]

然后构造：

[
r_t
===

\operatorname{Relation}
(
s_t^{target},
s_t^{reference},
s_t^{robot},
E_t
)
]

这才是真正对动作有用的东西。

因为机器人动作真正关心的不是：

> “book 的 latent 是 `[0.31,-0.18,...]`”

而是：

> **书相对于 gripper 在哪里？书有没有随着上一步动作运动？现在目标关系和期望关系差多少？**

SlotVLA引入 relation-centric encoder 的原因基本也是这个：object slot 本身提供对象表示，但 manipulation 还需要显式建模 object-object / gripper-object relations。([arXiv][1])

# 6. 于是 Recovery Adapter 可以改成真正的 Slot-conditioned Action Head

我建议让 8 个 future action query 去 cross-attend SlotSSM。

例如：

[
Q_A=
[q_1^A,\ldots,q_8^A]
]

然后：

[
C_A=
\operatorname{CrossAttn}
(
Q_A,,
K=[S_t;r_t;E_t],,
V=[S_t;r_t;E_t]
)
]

最后：

[
\hat A_t
========

\pi_R(C_A,p_t,L,m)
]

其中 (m) 是 recovery mode。

变成：

```text
                 SlotSSM
           s1 s2 s3 ... sK
                  │
       target / relation grounding
                  │
                  ▼
            Relation State r_t
                  │
        ┌─────────┴─────────┐
        │                   │
   recovery mode        8 Action Queries
                            │
                       Cross Attention
                            │
                            ▼
                       8-step Action
```

这时候每一个 action token 都必须从 object state 中取信息。

不过仅仅 Cross-Attention 依然不能保证模型一定使用 slot，所以前面的：

[
\mathcal L_{\text{dyn}}
]

非常重要。

一个负责**结构连接**，一个负责**训练约束**。

# 7. Candidate Verifier 其实也应该改

这可能是我对你当前方法最大的调整。

现在类似：

[
S_t
\rightarrow
\text{candidate verifier}
\rightarrow
m^*
]

比如：

```text
center
left
right
upper
lower
```

然后选择一个。

我觉得还是太抽象。

更合理应该是：

[
m
\rightarrow
\pi_R
\rightarrow
A_t^m
]

先得到 candidate action：

[
A_t^1,\ldots,A_t^M
]

然后用刚才那个 Slot Dynamics Model：

[
\hat S_{t+H}^{m}
================

F(S_t,A_t^m)
]

所以你真正 verifier 的对象变成：

[
\boxed{
V(
S_t,
A_t^m,
\hat S_{t+H}^{m},
L
)
}
]

预测：

[
q_m=P(\text{recovery success}\mid
S_t,A_t^m,\hat S_{t+H}^m,L)
]

然后：

[
m^*=\arg\max_m q_m
]

这一下 candidate verifier 的意义就彻底变了。

以前是：

> 我看当前图像，猜“往左”可能比较好。

现在是：

> 当前物体是这个状态；
> candidate 1 会产生这个动作；
> 这个动作预计会让 book/gripper/obstacle 变成这种关系；
> 因此判断它是否是可行 recovery。

这才是真正的 **candidate verifier**。

# 10. 还有一个非常现实的问题：为什么一定要 SlotSSM？

这个问题你写论文时 reviewer 很可能也会问。

如果 recovery 只是：

> 当前书偏左 → 往左抓一点。

那么事实上：

[
RGB_t+p_t\rightarrow A_t
]

就够了。

**根本不需要 SSM。**

所以你的 recovery failure 最好利用真正的 temporal information。

比如：

```text
t-8：gripper 接近 book
t-4：gripper closing
t-2：应该已经 grasp
t：gripper 上升

book slot：
位置基本没变
```

或者：

```text
之前 book 被抓起来
↓
运动过程中 book slot 突然脱离 gripper
↓
slip / drop
```

或者：

```text
正常动作预计 book 向右移动
↓
实际 book 被碰向左侧
↓
object displacement
```

这时 SlotSSM 的价值就非常明确：

[
\boxed{
\text{不是帮助机器人“看见物体”，
而是帮助机器人理解“我的动作对物体产生了什么结果”。}
}
]

这句话我觉得甚至可以成为你整个方法的核心思想。

先**保留 OFT 完全不动**。

不要现在就去大改 OpenVLA 7B。

你真正增加的是一个小闭环：

[
\boxed{
\text{SlotSSM}
\rightarrow
\text{Action-conditioned object dynamics}
\rightarrow
\text{action-effect mismatch}
\rightarrow
\text{recovery action}
}
]

其中最关键的新东西不是 Candidate Verifier，甚至也不是 Gate。

而是：

[
\boxed{
F(S_t,A_t)\rightarrow S_{t+H}
}
]

**只要这个模块建立起来，你一直担心的“SlotSSM 和 action 到底有什么关系”就有了一个非常具体的答案：action 是 Slot 状态转移的控制输入。**

而且这个 dynamics 模型不必只用少量 failure/recovery 数据训练。你现有的大量正常 LIBERO demonstration 都天然包含：

[
(S_t,A_t,S_{t+1})
]

可以先把 **action↔slot transition** 学出来，再用少量 failure/recovery data 学 gate、mode 和 recovery adapter。这一点从实际可做性上也比“直接指望几十条 recovery 数据把 SlotSSM 和 action 对齐”靠谱得多。OpenVLA-OFT本身采用连续 action chunk + L1 regression，保持其 normal policy 不动、外挂一个小型 recovery action head也是比较自然的工程路径。([arXiv][4])

我现在会把你们的核心从之前的 **“SlotSSM-based failure detection + candidate recovery”** 往 **“object-state transition mismatch driven recovery”** 上收。这个故事会更闭环，也更能解释为什么必须有 SlotSSM。

然后整个 recovery 都围绕这个闭环展开：

# 二、SlotSSM 在这里到底负责什么

不要再把 SlotSSM 理解成：

> 给 action head 提供一个额外视觉 feature。

我们要把它定义成：

[
\boxed{\text{机器人的 object-level state space}}
]

假设：

[
S_t={s_t^1,\ldots,s_t^K}
]

每一个 (s_t^i) 对应一个持续跟踪的物体。

原来的：

[
S_t=f(S_{t-1},I_t)
]

改成：

[
\boxed{
S_t=f_{\text{slot}}
(S_{t-1},I_t,I_t^{wrist},p_t,a_{t-1})
}
]

这里把：

* 上一步 action；
* proprio；
* 当前视觉；

一起作为状态更新信息。

因此 SlotSSM 学的不只是：

> book 在哪里。

还逐渐学习：

> gripper 做了什么以后，book 发生了什么。

Embodied-SlotSSM本来就强调 persistent object-centric memory，并利用 relation encoder 将对象状态与 action prediction 对齐；我们的关键扩展是进一步显式加入 **action-conditioned transition supervision**。([arXiv][2])

# 三、真正解决“Slot 和 Action 对不上”的模块：Object Dynamics

这是整个方法最关键的地方。

定义：

[
\boxed{
F_\phi(S_t,A_t,p_t)
\rightarrow
\hat S_{t+H}
}
]

你现在是 8-step action chunk，那么：

[
A_t=[a_t,\ldots,a_{t+7}]
]

于是：

[
F_\phi(S_t,A_t)
\rightarrow
\hat S_{t+8}
]

含义就是：

> 当前物体是这个状态，如果执行这 8 步动作，8 步以后这些物体应该是什么状态？

这就建立了：

[
\boxed{
S_t
\xrightarrow{A_t}
S_{t+8}
}
]

也就是：

[
\boxed{\text{Action} \leftrightarrow \text{Object State Transition}}
]

OA-WAM近期其实已经证明这种 object-addressable world/action 联合建模是可行方向：它同时维护 robot/object slots，预测下一状态 slot，并生成连续 action chunk。我们的区别可以放在 **failure detection + recovery + mismatch-driven control** 上。([arXiv][3])

这是你在 LIBERO 仿真里最大的优势。

因为你可以在**训练阶段**额外读取 simulator ground truth。

例如针对 book：

[

==========

[
position,
rotation,
relative\ pose\ to\ gripper,
grasp/contact
]

[
x_t^{robot}

[

gripper\ state
]
]

[

\rightarrow
x_t^{book}
]

所以 SlotSSM 不只是一个不可解释的 256 维 feature。

你通过辅助监督把它变成：

> **control-relevant object representation。**

例如损失：

[
\mathcal L_{\text{state}}
=========================

|\hat p^{obj}-p^{obj}|
+
\lambda_r\mathcal L_{\text{rot}}
+
\lambda_g\mathcal L_{\text{grasp}}
]

这些 simulator state **只用于训练**。

测试时依然：

```text
RGB
+wrist RGB
+instruction
+proprio
```

不输入 object pose。

这样论文还是视觉策略。

# 五、Failure Gate 也自然了

假设上一 chunk 时刻：

[

dynamics 预测：

[
\hat S_t=F(S_{t-8},A_{t-8})
]

现在真正看到新图像，SlotSSM得到：

[
S_t
]

计算：

[
\boxed{
E_t=d(S_t,\hat S_t)
}
]

这个就是 **Action-Effect Mismatch**。

比如抓书：

```text
执行动作：
close gripper + lift

预测：
book 应该跟 gripper 一起向上

实际：
gripper 向上
book 没动
```

于是：

[
E_t^{book}\gg0
]

这就是非常自然的 grasp failure signal。

Gate：

[
g_t=
G(S_t,\hat S_t,E_t,p_t,L)
]

输出：

[
g_t=P(\text{recovery})
]

所以现在 Gate 判断的是：

> **“执行结果是否符合动作预期？”**

而不是简单看图猜有没有失败。

---

# 六、Recovery Action 怎么真正受到 Slot 指导

这里还有一个非常重要的设计。

只做：

[
S_t\rightarrow\hat A_t
]

还是可能忽略 Slot。

所以我建议 recovery adapter 训练时同时加两种监督。

第一种是正常 action imitation：

[
\mathcal L_{\text{act}}
=======================

|\hat A_t-A_t^*|_1
]

这与 OpenVLA-OFT 的 continuous action regression 思路一致。([arXiv][4])

但第二个才真正重要：

[
\boxed{
\mathcal L_{\text{effect}}
==========================

d
\left(
F_\phi(S_t,\hat A_t),
S_{t+8}^*
\right)
}
]

注意这里的区别。

action head 输出：

[
\hat A_t
]

然后把这个 action **重新丢进已经训练好的 dynamics model**：

[
F_\phi(S_t,\hat A_t)
]

看它预计把物体带到哪里。

我们希望：

[
F_\phi(S_t,\hat A_t)
\approx
S_{t+8}^{expert}
]

所以训练 recovery adapter 时：

[
\boxed{
\mathcal L_R
============

\mathcal L_{\text{act}}
+
\lambda_{\text{effect}}
\mathcal L_{\text{effect}}
}
]

而且这个阶段我建议：

[
\boxed{F_\phi\text{ 冻结}}
]

否则 dynamics model 自己改变预测来迎合 action head，约束会失效。

这一步才是真正把：

[
\boxed{\text{Slot state}\rightarrow\text{Action}\rightarrow\text{Slot change}}
]

锁起来。

---

# 七、Candidate Verifier 也相应改掉

你以前：

[
S_t\rightarrow verifier\rightarrow mode
]

例如：

```text
center
left
right
upper
lower
```

现在改成：

对于每个 recovery mode (m)：

[
A_t^m
=====

\pi_R(S_t,E_t,R_t,m)
]

其中 (R_t) 是：

[
R_t=
[
target\leftrightarrow gripper,
target\leftrightarrow reference
]
]

然后预测这个 candidate 执行之后的结果：

[
\hat S_{t+8}^m
==============

F_\phi(S_t,A_t^m)
]

Verifier：

[
q_m=
V(S_t,A_t^m,\hat S_{t+8}^m,L)
]

最后：

[
m^*=\arg\max_m q_m
]

所以 verifier 不再是：

> “看图片猜 left 好还是 right 好。”

而是：

> “如果执行 left，对象预计会到这里；
> 如果执行 right，对象预计会到那里；
> 哪一个 future state 更可能完成任务？”

这就合理很多。

# 八、你到底需要什么数据

我建议把数据明确分成 **三类**。

| 数据                | 用途                           | 来源                        |
| ----------------- | ---------------------------- | ------------------------- |
| (D_{\text{dyn}})  | 学 action → object transition | LIBERO demos + 自己 rollout |
| (D_{\text{fail}}) | 学 Failure Gate               | OFT 在扰动环境中的失败轨迹           |
| (D_{\text{rec}})  | 学 recovery action + verifier | 从同一失败状态分叉执行多个 candidate   |

每条 transition 最好保存：

```text
source_id
task_id
instruction

RGB_t
wrist_RGB_t
proprio_t
action_prev

slot/object simulator state_t

action_chunk_t:t+7

RGB_t+8
wrist_RGB_t+8
proprio_t+8
object simulator state_t+8

candidate_mode
candidate_success

episode_success
failure_type
```

其中最重要的是：

[
\boxed{
(S_t,A_t,S_{t+8})
}
]

# 九、Dynamics 数据不要只用成功轨迹

这一点非常重要。

LIBERO-Plus论文自己构造 generalized training data 时，采用了与测试不同参数的自动化扰动环境，并保留了超过 20,000 条成功轨迹；官方最终 LIBERO-Plus 本身则是 **10,030 个 test-only evaluation tasks**。([arXiv][5])

对于普通 robustness training，成功轨迹够用。

但是你的 dynamics 不一样。

它必须知道：

```text
close gripper
↓
book 被抓住

以及

close gripper
↓
book 没被抓住
```

所以你一定要加入：

[
\boxed{\text{failed interaction transitions}}
]

否则 dynamics 永远只看过：

> 正确 action → 正确 object movement。

遇到失败以后，它根本不知道实际可能发生什么。

因此：

[
D_{\text{dyn}}
==============

D_{\text{success}}
\cup
D_{\text{failure}}
\cup
D_{\text{candidate}}
]

最合理。

# 十、LIBERO-Plus 里怎么采 failure 数据

先冻结 OpenVLA-OFT。

然后在自己生成的 perturbation training environments 中 rollout。

我建议第一版先做：

[
\boxed{\text{Robot Initial States}}
]

因为当前 LIBERO-Plus官方结果里 OpenVLA-OFT 在 Robot perturbation 上只有约 **31.9%** success，天然会产生大量 failure，很适合做 recovery 数据。([GitHub][6])

以后再扩：

[
Robot \rightarrow Camera \rightarrow Layout
]

因为这三个更直接涉及 geometry / visuomotor recovery。

# 十一、Recovery 数据应该怎么采

这个地方仿真特别方便。

假设 OFT 跑到某个失败状态：

[
s_f
]

**保存 simulator state。**

然后从同一个 (s_f) 分叉：

```text
                    failure state sf
                           │
          ┌────────┬───────┼───────┬────────┐
          ▼        ▼       ▼       ▼        ▼
       center    left    right    upper    lower
          │        │       │       │        │
          ▼        ▼       ▼       ▼        ▼
        rollout  rollout  rollout  rollout  rollout
          │        │       │       │        │
          ▼        ▼       ▼       ▼        ▼
          1        0       1       0        0
```

于是对于同一个 state：

[
{(s_f,A^m,y_m)}_{m=1}^M
]

这正好训练 verifier。

而且你之前强调的数据约束仍然应该保留：

> 同一个 source failure 的所有 candidates 必须在同一个 train/val/test split。

否则会 source leakage。

# 十二、训练顺序我建议固定成 5 个 Stage

这是我认为最实际的训练方案。

### Stage 1：训练 SlotAttention + SlotSSM

输入：

[
I_{1:t},I^{wrist}*{1:t},p*{1:t},a_{1:t-1}
]

目标：

* stable object slots；
* temporal identity；
* simulator object-state auxiliary prediction。

得到：

[
S_t
]

这里可以从 Embodied-SlotSSM 的 object-centric temporal memory 开始改。([arXiv][1])

---

### Stage 2：训练 Object Dynamics

训练：

[
F_\phi(S_t,A_t,p_t)
\rightarrow
S_{t+8}
]

损失建议：

[
\mathcal L_{\text{dyn}}
=======================

\lambda_s
d(\hat S,S)
+
\lambda_p
\mathcal L_{\text{pose}}
+
\lambda_r
\mathcal L_{\text{relation}}
+
\lambda_g
\mathcal L_{\text{grasp}}
]

这一阶段先不要训练 recovery。

你首先要验证一件事：

[
\boxed{\text{给定当前对象状态和 action，能不能预测对象之后怎么变化？}}
]

如果这件事情都学不好，后面的 recovery 不值得继续堆。

---

### Stage 3：训练 Failure Gate

现在 dynamics 已经能够预测：

[
\hat S_t
]

真实 observation 给：

[
S_t
]

构造：

[
E_t=S_t-\hat S_t
]

训练：

[
G(S_t,\hat S_t,E_t)
\rightarrow
y_t^{failure}
]

loss：

[
\mathcal L_{\text{gate}}
========================

BCE(\hat y_t,y_t)
]

failure label 可以先利用 simulator 自动生成，不需要手工一帧一帧标。

---

### Stage 4：训练 Recovery Adapter

输入：

[
[S_t,E_t,R_t,L,p_t,m]
]

输出：

[
\hat A_t^{m}
]

训练：

[
\boxed{
\mathcal L_R
============

\mathcal L_{\text{act}}
+
\lambda_e\mathcal L_{\text{effect}}
}
]

其中：

[
\mathcal L_{\text{effect}}
==========================

d(
F_\phi(S_t,\hat A_t),
S_{t+8}^*
)
]

这个阶段：

[
\boxed{\text{freeze }F_\phi}
]

这是我认为整套方案里**最关键的训练技巧**。

---

### Stage 5：训练 Candidate Verifier

对于同一个 failure state：

[
A^1,\ldots,A^M
]

预测：

[
\hat S^1,\ldots,\hat S^M
]

然后：

[
V(S_t,A^m,\hat S^m,L)
\rightarrow q_m
]

训练 BCE：

[
\mathcal L_{\text{ver}}
=======================

BCE(q_m,y_m)
]

再加一个同状态 pairwise ranking：

如果：

[
y_i=1,\quad y_j=0
]

要求：

[
q_i>q_j
]

这样 verifier 更直接学习：

> 同一个 failure state 下哪个 candidate 更好。

# 十三、OpenVLA-OFT 第一版最好不要联合训练

我建议：

```text
OpenVLA-OFT
    ↓
完全冻结
```

它继续负责：

[
A_t^N

你的新模块负责：

```text
SlotAttention
SlotSSM
Dynamics
Gate
Recovery Adapter
Verifier
```

这样实验也非常干净：

[
\text{OFT}
]

vs

[
\text{Frozen OFT + Ours}
]

不会有人说：

> 是不是因为你把 OFT 又重新训练了一遍所以变强了？

OpenVLA-OFT目前本来就是强 LIBERO baseline，并采用 parallel continuous action-chunk decoding，因此冻结 base policy、外挂 recovery branch 是很自然的工程起点。([arXiv][7])

# 十五、最终你论文真正要证明的 4 件事

这四个实验基本决定这套方法是否成立。

| 问题                                           | 实验                                 |
| -------------------------------------------- | ---------------------------------- |
| Action 是否真的和 Slot 对齐？                        | Slot Dynamics prediction error     |
| Gate 是否因为 action-effect mismatch 检出 failure？ | Failure AUROC / F1 / latency       |
| Verifier 是否真的按状态选 recovery？                  | Uniform / Fixed / Learned / Oracle |
| 整体是否真的救回任务？                                  | Recovery Rate + Final Task Success |

除此之外，我强烈建议再做一个非常有杀伤力的实验：

### Slot intervention

正常输入：

[
S_t^{book}
\rightarrow A
]

然后：

**Mask target slot：**

[
S_t^{book}=0
]

或者：

**把 book slot 和另一个 object slot swap。**

看 recovery action 是否明显改变、success 是否下降。

如果结果：

```text
Full model               70%
mask target slot         42%
swap target slot         35%
w/o dynamics loss        48%
```

那你就真正证明了：

[
\boxed{\text{Recovery policy 确实依赖 object slot}}
]

而不只是“网络里有一个 SlotSSM”。

# 十六、所以你现在实际应该怎么做

按优先级，我建议只有这一条执行路线：

1. **先冻结 OFT，别动 7B backbone。**
2. 在 LIBERO / 自建非测试 perturbation 环境中保存完整的
   ((I_t,I_t^{wrist},p_t,A_t,I_{t+8})) transitions。
3. 同时保存 simulator 的 target-object pose、EEF pose、gripper/contact 等训练辅助标签。
4. 训练 SlotAttention + Action-conditioned SlotSSM。
5. 训练
   [
   F(S_t,A_t)\rightarrow S_{t+8}
   ]
   先证明 object dynamics 能学出来。
6. 用 OFT 在 Robot perturbation 下大量 rollout，收集真实 failure transitions。
7. 从每个 failure simulator state 分叉运行多个 recovery candidate。
8. 用 dynamics mismatch 训练 failure gate。
9. 冻结 dynamics，训练 recovery adapter：
   [
   L_{\text{act}}+\lambda L_{\text{effect}}
   ]
10. 用同 source 多 candidate success/failure 数据训练 verifier。
11. 最终部署：
    [
    OFT\rightarrow observe\rightarrow mismatch\rightarrow recovery\rightarrow observe
    ]
    闭环执行。
12. checkpoint 锁定以后，再读官方 LIBERO-Plus test tasks 做最终结果。

## 最后把整个方法压缩成一句话

我现在认为你这篇方法最合理的核心已经不是：

> **用 SlotSSM 检测失败并生成恢复动作。**

而应该升级成：

[
\boxed{
\textbf{Learn how robot actions transform object-centric states,
detect failures from action-effect mismatch,
and generate recovery actions that restore the desired object-state transition.}
}
]

中文就是：

> **学习机器人动作与对象状态转移之间的关系，通过“预期动作效果—实际对象变化”的不一致检测失败，并生成能够恢复目标对象状态转移的动作。**

这样 **SlotSSM 为什么存在、Previous Action 为什么存在、Gate 为什么这样判断、Recovery Action 为什么受 Slot 指导、Verifier 为什么能够选择 candidate**，五件事情就全部被同一个核心机制串起来了。
