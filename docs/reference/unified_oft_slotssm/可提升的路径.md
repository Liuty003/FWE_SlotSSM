可以，而且我觉得你们**不用推翻现在这套思路**。最自然的改法是：

> **保留“失败触发 + 离散恢复模式”这个结构，但把现在推理阶段的 FSM 局部程序全部蒸馏成神经网络动作头。FSM 只负责造训练数据，部署时完全不用 FSM。**

这样就能变成一个真正意义上的、针对“取书类任务”的端到端策略。

你们当前方法的问题在这里：

[
\text{obs}\rightarrow\text{selector}\rightarrow\boxed{\text{人工 FSM}}\rightarrow a
]

中间有人工控制逻辑，所以整体不是端到端。

我建议改成：

[
\text{obs/history}
\rightarrow
\text{OFT backbone + SlotSSM}
\rightarrow
\begin{cases}
\text{normal action head}\
\text{recovery mode + recovery action head}
\end{cases}
\rightarrow a_t
]

核心结构如下。

---

## 1. 保留 OFT+ 正常策略

正常情况下仍然：

[
a_t^{N}=f_{\text{OFT}}(I_t,L,p_t)
]

不要重新学“正常取书”。

这样原来 OFT+ 能成功的能力基本保留。

---

## 2. SlotSSM 继续负责判断是否进入 recovery

输入：

[
H_t=
{
h_t^{OFT},
s_t^{slot},
p_t,
a_{t-1}
}
]

输出：

[
g_t=P(\text{recovery}|H_t)
]

然后：

[
g_t<\tau
\Rightarrow
a_t=a_t^N
]

[
g_t>\tau
\Rightarrow
进入 recovery policy
]

这一部分你们现在基本已经有了。

---

# 3. 最大改动：不要让 selector 后面接 FSM

现在是：

[
H_t
\rightarrow
c_i
\rightarrow
FSM_i
\rightarrow
a_t
]

改成：

[
H_t
\rightarrow
c_i
\rightarrow
\boxed{\pi_i(H_t)}
\rightarrow
a_t
]

也就是说五个 candidate 不再是五套人工程序，而变成 **5 个 learned recovery experts**。

例如：

[
\pi_0 = \text{center recovery expert}
]

[
\pi_1 = \text{left-longitudinal expert}
]

[
\pi_2 = \text{right-longitudinal expert}
]

[
\pi_3 = \text{left-lateral expert}
]

[
\pi_4 = \text{right-lateral expert}
]

selector：

[
q_t=\operatorname{softmax}(W H_t)
]

选择：

[
k=\arg\max_i q_{t,i}
]

然后：

[
a_t^{R}=\pi_k(H_t)
]

最终：

[
a_t=
(1-g_t)a_t^N
+
g_ta_t^R
]

这样**从图像一直到机器人动作都是 neural policy**。

---

# 4. 这样还能解决你之前的“平均动作”问题

你们之前最麻烦的是：

不同恢复轨迹一起回归：

```text
左边抓
右边抓
中间抓
↓
一个连续动作头
↓
平均
↓
撞书 / 抓空
```

如果直接训练：

[
\pi_R(H_t)\rightarrow a_t
]

还是可能发生这个问题。

但现在加入离散 mode：

[
\pi(H_t,c_i)\rightarrow a_t
]

等于先解决 multimodality：

```text
当前状态
   ↓
选 recovery mode
   ↓
left / right / center ...
   ↓
该 mode 内连续动作回归
```

所以：

> **离散 mode 负责解决“往哪边恢复”，连续 action head 负责解决“具体怎么运动”。**

我觉得这是你们当前思路最适合的端到端版本。

# 5. FSM 怎么办？

**FSM 不要删，它变成 teacher。**

你们现在已经可以：

```text
失败状态
↓
运行 5 个 FSM candidate
↓
得到 5 条恢复轨迹
↓
知道哪个成功
```

那直接保存：

[
D_R=
{
(I_t,p_t,a_t,c_i,y_i)
}
]

其中：

* (c_i)：用了哪个 recovery mode
* (a_t)：FSM 实际执行动作
* (y_i)：最终是否恢复成功

然后训练两个东西。

### selector

[
\mathcal L_{sel}
================

CE(q_t,c^*)
]

其中 (c^*) 是成功 candidate。

### recovery action policy

[
\mathcal L_{act}
================

\sum_t
|
\pi_R(H_t,c^*)-a_t^{FSM}
|_1
]

或者继续用 OFT 的 action chunk loss。

于是：

**训练阶段：**

[
FSM\rightarrow teacher
]

**部署阶段：**

[
\boxed{FSM\ completely\ removed}
]

这才是我建议你们做的。

---

# 6. 最好不要真的做 5 个完全独立网络

没必要。

做一个共享 recovery head：

[
a_t^R
=====

f_R(H_t,e(c_i))
]

其中：

[
e(c_i)
]

是五种 recovery mode 的 embedding。

比如：

```text
OFT hidden
SlotSSM hidden
proprio
mode embedding
      │
      ▼
Recovery Action Head
      │
      ▼
action chunk
```

也就是：

[
[H_t;e(c_i)]
\rightarrow
\text{MLP / Transformer action head}
\rightarrow
a_{t:t+K}
]

这样参数少很多。

实际上我会推荐：

> **一个 selector + 一个 mode-conditioned recovery head**

而不是五个 recovery head。

---

# 7. 更进一步，可以连 selector 都做成 latent

你们第一版不要这么干，但最终完全可以变成：

[
q(c|H_t)
]

和

[
\pi(a|H_t,c)
]

联合训练。

最终策略：

[
\pi(a|H_t)
==========

\sum_{c=1}^{5}
q(c|H_t)\pi(a|H_t,c)
]

这本质上就是一个 **Mixture-of-Experts / latent-mode policy**。

不过推理时我更建议 hard routing：

[
c^*=\arg\max q(c|H_t)
]

[
a=\pi(a|H_t,c^*)
]

不要做五个动作加权平均，否则又可能把左右动作混在一起。

---

# 8. 闭环怎么保留？

这个非常关键。

你现在 FSM：

```text
抬起
↓
横移
↓
下探
↓
闭爪
↓
抬起
```

是显式闭环。

换成网络后，不要一次预测完整 3 秒轨迹直接执行。

用 action chunk：

[
a_{t:t+K}
=========

\pi_R(H_t,c)
]

但只执行前面几步：

[
a_t,\ldots,a_{t+m}
]

然后重新观察：

[
I_{t+m},p_{t+m}
]

再重新预测。

也就是：

```text
observe
↓
predict 8-step chunk
↓
execute 2~4 steps
↓
observe again
↓
predict again
```

这样仍然是 closed-loop。

而且非常适合 OFT 本身的 action chunk 体系。

# 10. 我认为你们现在最适合做的版本

不要追求：

[
\text{一个大 VLA 同时从头学正常+失败恢复}
]

数据根本不够，而且非常容易把 OFT+ 正常能力训坏。

你们应该做的是一个**端到端 hierarchical policy**：

[
\boxed{
\text{OFT+ normal policy}
+
\text{learned recovery gate}
+
\text{learned discrete mode selector}
+
\text{learned mode-conditioned recovery policy}
}
]

其中唯一手工的东西是：

> **训练数据生成阶段用 FSM 产生 recovery demonstrations。**

部署时：

[
\boxed{\text{image/history}\rightarrow\text{neural network}\rightarrow\text{robot action}}
]

没有人工 FSM。

所以你问“能不能做成端到端”：

**完全可以，而且你们现在的方法只差最后一步：把 FSM 从 inference controller 改成 training teacher。**

我认为这比直接把“五个候选”扔掉、重新训练一个连续 recovery head靠谱得多。
