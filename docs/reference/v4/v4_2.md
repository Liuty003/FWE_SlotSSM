下面把当前方案固定成一版。**先冻结整个 OpenVLA-OFT，包括 action decoder**；后续如果发现 frozen decoder 限制 recovery action 表达能力，再单独做 decoder LoRA ablation。

核心思想只有一句：

[
\boxed{
\text{Failure detection 和 Recovery generation 共享同一份 task-conditioned relational context}
}
]

也就是：

[
\boxed{
\text{Entities}
\rightarrow
\text{3D Relations}
\rightarrow
\text{Task-conditioned Retrieval}
\rightarrow
{\text{Detect},\text{Correct}}
}
]

---

# 1. 整体结构

```text
RGB / Wrist RGB / Depth / Instruction / Proprio
                      │
                      ▼
              Frozen OpenVLA-OFT
              /                 \
             /                   \
     Visual Tokens V_t      Action Hidden H_t^a
             │                   │
             ▼                   │
       Slot Attention            │
             │                   │
   Slots z_t^1 ... z_t^K         │
   + Slot Masks M_t^i            │
             │                   │
      Depth + Camera Pose        │
             │                   │
             ▼                   │
       Robot-frame 3D Objects    │
       p_t^1 ... p_t^K           │
             │                   │
             ▼                   │
        Relation Set R_t         │
   gripper↔obj / obj↔obj         │
             │                   │
             └────────┬──────────┘
                      ▼
               Cross-Attention
          Q = H_t^a, K,V = R_t
                      │
                      ▼
            Relational Context C_t
               /              \
              ▼                ▼
        Failure Gate      Recovery Adapter
             │                │
            g_t              ΔH_t
             │                │
             └───────┬────────┘
                     ▼
          H̃_t^a = H_t^a + m_t αΔH_t
                     │
                     ▼
          SAME Frozen OFT Decoder
                     │
                     ▼
             8-step Action Chunk
```

其中最关键的中间变量是：

[
\boxed{C_t}
]

它同时回答：

> 当前任务相关的物理关系是否异常？

以及：

> 如果异常，应该怎样修改 OFT 当前动作？

# 2. OFT：保持正常策略能力

当前输入：

[
\boxed{
O_t={I_t^m,I_t^w,L,p_t}
}
]

其中：

* (t)：当前策略决策时刻；
* (I_t^m)：主相机 RGB；
* (I_t^w)：wrist RGB；
* (L)：语言指令；
* (p_t)：机器人 proprioception；
* (O_t)：当前 observation。

Frozen OFT 得到：

[
\boxed{
H_t^a=\operatorname{OFT}_{enc}(O_t)
}
]

其中：

* (H_t^a)：OFT 在 action decoder 前的 language-conditioned action hidden tokens；
* 上标 (a)：action representation。

正常动作：

[
\boxed{
A_t^N=D_{\mathrm{OFT}}(H_t^a)
}
]

其中：

* (D_{\mathrm{OFT}})：原 OFT action decoder；
* (A_t^N)：normal action chunk。

**当前版本中 OFT backbone 和 (D_{\mathrm{OFT}}) 全部冻结。**

---

# 3. Slot：把场景拆成实体

从 OFT visual tokens：

[
V_t={v_t^1,\ldots,v_t^N}
]

得到：

[
\boxed{
Z_t=SA_\theta(V_t)
}
]

[
Z_t={z_t^1,\ldots,z_t^K}
]

其中：

* (SA_\theta)：Slot Attention；
* (\theta)：Slot Attention 参数；
* (N)：dense visual token 数；
* (K)：slot 数；
* (z_t^i)：第 (i) 个对象的视觉/语义 slot。

同时得到 soft mask：

[
\boxed{
M_t^i(u,v)
}
]

其中：

* (M_t^i)：第 (i) 个 slot 对应的图像区域；
* ((u,v))：像素位置。

Slot 只回答：

[
\boxed{\text{场景里有哪些实体？}}
]

不预先规定谁是 target、谁是 receptacle。

---

# 4. Slot → Robot-frame 3D Geometry

当前主版本直接利用 LIBERO 中的 depth 和 camera calibration，不额外训练 RGB→3D head。

利用 slot mask 和 depth：

[
\boxed{
P_t^{i,C}
=========

\Pi^{-1}(M_t^i,D_t,K_C)
}
]

其中：

* (D_t)：depth image；
* (K_C)：camera intrinsic matrix；
* (\Pi^{-1})：2D depth pixel 到 3D point 的反投影；
* (P_t^{i,C})：第 (i) 个对象在 camera frame 下的 3D point cloud；
* 上标 (C)：camera coordinate frame。

再变换到机器人坐标系：

[
\boxed{
P_t^{i,R}
=========

T_{C\rightarrow R}P_t^{i,C}
}
]

其中：

* (T_{C\rightarrow R})：camera frame 到 robot base frame 的外参变换；
* (P_t^{i,R})：robot frame 下的 3D points；
* 上标 (R)：robot frame。

得到对象中心：

[
\boxed{
p_t^i=\operatorname{Pool}(P_t^{i,R})
}
]

其中：

* (p_t^i\in\mathbb R^3)：对象 (i) 的 robot-frame 3D position。

这样 camera viewpoint 改变后，最终所有关系仍统一在 robot frame。

---

# 5. 构造 3D Relation Tokens

## 5.1 Gripper–Object Relation

gripper 位置：

[
p_t^g
]

来自 proprio。

定义相对位置：

[
\boxed{
\Delta p_t^{g,i}=p_t^i-p_t^g
}
]

距离：

[
\boxed{
d_t^{g,i}
=========

|\Delta p_t^{g,i}|_2
}
]

然后：

[
\boxed{
r_t^{g,i}
=========

\phi_g
\left(
[z_t^i;\Delta p_t^{g,i};d_t^{g,i}]
\right)
}
]

其中：

* (g)：gripper；
* (i)：第 (i) 个 object；
* (r_t^{g,i})：gripper-object relation token；
* (\phi_g)：小型 relation MLP；
* ([,;,])：向量拼接；
* (d_t^{g,i})：gripper-object Euclidean distance。

---

## 5.2 Object–Object Relation

对于对象 (i,j)：

[
\boxed{
\Delta p_t^{i,j}
================

p_t^j-p_t^i
}
]

然后：

[
\boxed{
r_t^{i,j}
=========

\phi_o
\left(
[z_t^i;z_t^j;\Delta p_t^{i,j}]
\right)
}
]

其中：

* (r_t^{i,j})：object-object relation；
* (\phi_o)：object relation MLP。

最终：

[
\boxed{
R_t=
{r_t^{g,i}}*{i=1}^{K}
\cup
{r_t^{i,j}}*{i\ne j}
}
]

其中：

* (R_t)：当前 candidate relation set；
* (M=|R_t|)：relation token 数量。

第一版可以限制 (K)，避免所有无意义 pair 导致关系数过多。

---

# 6. 怎么知道哪个 Relation 和当前任务相关？

**不训练 target/container classifier。**

因为：

[
H_t^a
]

已经融合了 instruction：

> Put ketchup into basket.

所以直接让 OFT 当前 action intent 查询所有 relations：

[
\boxed{
C_t=
\operatorname{CrossAttn}
(
H_t^a,
R_t,
R_t
)
}
]

对应：

[
Q=H_t^a,\qquad K=R_t,\qquad V=R_t
]

其中：

* (Q)：Query；
* (K,V)：Key 和 Value；
* (C_t)：**Task-Conditioned Relational Context**。

例如模型可以自动重点读取：

[
r_t^{g,ketchup}
]

以及：

[
r_t^{ketchup,basket}.
]

因此：

[
\boxed{
\text{Relation 描述世界；
OFT language-conditioned action intent 选择当前任务 relevant relations。}
}
]

# 7. Failure Gate

不再额外构造 failure signal (f_t)。

直接从：

[
C_t
]

判断：

[
\boxed{
g_t
===

\sigma
\left(
G_\psi(
\operatorname{Pool}(C_t)
)
\right)
}
]

其中：

* (G_\psi)：Failure Gate；
* (\psi)：Gate 参数；
* (\operatorname{Pool})：token pooling；
* (\sigma)：sigmoid；
* (g_t\in[0,1])：需要 recovery 的概率。

Gate 学习的问题是：

[
\boxed{
\text{当前 task-relevant physical relations 是否还适合 nominal policy 继续执行？}
}
]

---

# 8. Recovery Adapter

同一份：

[
C_t
]

直接产生 recovery correction：

[
\boxed{
\Delta H_t
==========

W_oR_\rho(C_t)
}
]

其中：

* (R_\rho)：Recovery Adapter；
* (\rho)：Adapter 参数；
* (W_o)：输出 projection；
* (\Delta H_t)：对 OFT action representation 的 correction。

要求：

[
\Delta H_t,H_t^a
\in
\mathbb R^{T_a\times d}
]

其中：

* (T_a)：action-side token 数；
* (d)：OFT hidden dimension。

---

# 9. Gated Residual Correction

最终：

[
\boxed{
\tilde H_t^a
============

H_t^a+
m_t\alpha\Delta H_t
}
]

其中：

* (\tilde H_t^a)：修正后的 action representation；
* (m_t\in{0,1})：是否启用 recovery；
* (\alpha)：residual correction scale。

### 训练时

使用 ground-truth gate：

[
\boxed{
m_t=y_t
}
]

避免训练早期 Gate 判断错误影响 recovery learning。

### 推理时

[
\boxed{
m_t=
\mathbf1[g_t>\tau]
}
]

其中：

* (\tau)：Gate threshold；
* (\mathbf1[\cdot])：indicator function。

---

# 10. 最终 Action

当前先保持 action decoder 冻结：

[
\boxed{
\hat A_t
========

D_{\mathrm{OFT}}
(
\tilde H_t^a
)
}
]

正常：

[
m_t=0
]

则：

[
\boxed{
\hat A_t
========

D_{\mathrm{OFT}}(H_t^a)
}
]

完全等于原 OFT。

Recovery：

[
m_t=1
]

则：

[
\boxed{
\hat A_t
========

D_{\mathrm{OFT}}
(
H_t^a+\alpha\Delta H_t
)
}
]

第一版先验证 frozen decoder 是否已经足够。

之后做：

[
\text{Frozen Decoder}
\quad vs\quad
\text{Recovery LoRA}
]

再决定是否开放 decoder adaptation。

# 11. 需要训练什么？

## 冻结

[
\boxed{
\text{OpenVLA-OFT backbone}
+
\text{OFT action decoder}
}
]

---

## 训练

只有四部分：

[
\boxed{\text{Slot Attention }SA_\theta}
]

[
\boxed{\text{Relation Encoders }\phi_g,\phi_o}
]

[
\boxed{\text{Cross-Attention + Recovery Adapter }R_\rho}

\boxed{\text{Failure Gate }G_\psi}

* future prediction；

# 12. 训练数据

只需要两大类。

## A. Normal Data

[
\boxed{
D_N=
{O_t,y_t=0}
}
]

来源：

* LIBERO demonstrations；
* Frozen OFT 成功 rollout；
* training perturbation 中正常 segment。

其中：

* (D_N)：normal dataset；
* (y_t=0)：当前不需要 recovery。

主要监督 Gate。

---

## B. Failure-Recovery Data

Frozen OFT 在 training perturbation 环境中 rollout：

```text
OFT normal execution
        ↓
进入 failure/off-nominal state
        ↓
save simulator state
        ↓
teacher / FSM recovery
        ↓
successful recovery trajectory
        ↓
handoff back to OFT
```

得到：

[
\boxed{
D_R=
{
O_t,
y_t=1,
A_t^{R*}
}
}
]

其中：

* (D_R)：recovery dataset；
* (y_t=1)：当前处于 recovery segment；
* (A_t^{R*})：teacher/FSM 的成功 recovery action chunk；
* (^*)：ground truth / teacher supervision。

---

# 13. Failure Gate 监督

预测：

[
g_t
]

标签：

[
y_t\in{0,1}
]

使用：

[
\boxed{
\mathcal L_{\mathrm{gate}}
==========================

\operatorname{BCE}(g_t,y_t)
}
]

其中：

* (\mathcal L_{\mathrm{gate}})：failure detection loss；
* BCE：Binary Cross Entropy。

这条 loss 会反向训练：

[
C_t
\rightarrow
CrossAttn
\rightarrow
Relation Encoder
\rightarrow
Slot
]

使 (C_t) 学会区分：

[
\text{nominal relation}
\quad vs\quad
\text{recovery-needed relation}.
]

---

# 14. Recovery Action 监督

设 action chunk 长度：

[
H=8
]

模型输出：

[
\hat A_t=
[\hat a_{t,1},\ldots,\hat a_{t,H}]
]

teacher：

[
A_t^{R*}
========

[a_{t,1}^{R*},\ldots,a_{t,H}^{R*}]
]

使用：

[
\boxed{
\mathcal L_{\mathrm{rec}}
=========================

\frac1H
\sum_{h=1}^{H}
\left|
\hat a_{t,h}
------------

a_{t,h}^{R*}
\right|_1
}
]

其中：

* (h)：chunk 内第 (h) 个动作；
* (\hat a_{t,h})：预测动作；
* (a_{t,h}^{R*})：teacher recovery action；
* (|\cdot|_1)：L1 distance。

只在：

[
y_t=1
]

的 recovery samples 上计算。

这条 loss 直接让：

[
\boxed{
\text{Relation Context}
\rightarrow
\text{Corrective Action}
}
]

对齐。

---

# 15. Slot 的监督

为了防止 Slot Attention 不稳定，LIBERO 仿真训练阶段可以利用 object segmentation mask。

[
\boxed{
\mathcal L_{\mathrm{slot}}
==========================

\operatorname{MaskLoss}
(
M_t,M_t^*
)
}
]

其中：

* (M_t)：Slot Attention 预测 masks；
* (M_t^*)：simulator object segmentation；
* (\mathcal L_{\mathrm{slot}})：slot decomposition loss。

这是训练期 privileged supervision。

测试时不需要 simulator mask。

---

# 16. 总 Loss

最终只保留：

[
\boxed{
\mathcal L
==========

\lambda_g\mathcal L_{\mathrm{gate}}
+
\lambda_r\mathcal L_{\mathrm{rec}}
+
\lambda_s\mathcal L_{\mathrm{slot}}
}
]

其中：

* (\mathcal L)：总训练损失；
* (\lambda_g)：Gate loss 权重；
* (\lambda_r)：Recovery loss 权重；
* (\lambda_s)：Slot loss 权重。

Relation 不需要单独 relation label。

因为：

[
\mathcal L_{\mathrm{gate}}
+
\mathcal L_{\mathrm{rec}}
]

会共同训练：

[
R_t\rightarrow C_t.
]

# 17. 训练流程

只分两步。

### Step 1：Slot 初始化

利用 LIBERO 图像 + simulator segmentation：

[
RGB
\rightarrow
SlotAttention
\rightarrow
Object Slots
]

得到稳定 object decomposition。

### Step 2：Joint Recovery Training

加载：

```text
Frozen OFT
+
Slot Attention
+
Relation Encoder
+
Cross-Attention
+
Gate
+

```

使用：

[
D_N\cup D_R
]

  [

  [

# 18. 论文核心故事

我们的重点不是：

> Relations 可以用于机器人动作。

这个已经有工作做过。

我们的命题是：

[
\boxed{
\textbf{Task-conditioned physical relations provide a corrective interface for recovering pretrained VLAs.}
}
]

正常时：

[
\boxed{\text{OFT负责 task progression}}
]

失败后：

[
\boxed{\text{Relation branch负责 local physical correction}}
]

同一个：

[
C_t
]

同时用于：

[
\boxed{
C_t
\rightarrow
\begin{cases}
\text{Should I recover?}\
\text{How should I recover?}
\end{cases}
}
]

最终方法可以压缩成五条公式：

[
\boxed{
Z_t=SA_\theta(V_t)
}
]

[
\boxed{
R_t=\operatorname{Rel}(Z_t,\text{3D geometry},p_t)
}
]

[
\boxed{
C_t=\operatorname{CrossAttn}(H_t^a,R_t,R_t)
}
]

[
\boxed{
g_t=\sigma(G_\psi(\operatorname{Pool}(C_t))),
\qquad
\Delta H_t=W_oR_\rho(C_t)
}
]

[
\boxed{
A_t=
D_{\mathrm{OFT}}
\left(
H_t^a+m_t\alpha\Delta H_t
\right)
}
]

这版我建议作为当前代码实现的主线。之后最先验证两个问题：**Relation 是否显著优于 Global/Slot recovery，以及 frozen decoder 是否足够表达 recovery actions。**
