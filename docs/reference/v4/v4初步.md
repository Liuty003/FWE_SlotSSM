可以。现在把方案收敛成一版，不再引入 SlotSSM、(E_t)、world model、candidate verifier 等额外模块。

核心命题：

[
\boxed{\text{Recovery = task-conditioned relational correction}}
]

即：**OFT 已经负责正常任务推进；失败后，显式读取与当前指令相关的 robot–object / object–goal 3D 关系，对 OFT 的动作表示做局部修正。**

# 1. 整体结构

```text
RGB / Wrist RGB / Instruction / Proprio
                    │
                    ▼
             Frozen OpenVLA-OFT
              /               \
             /                 \
      Visual Tokens V_t      Action Hidden H_t^a
             │                    │
             ▼                    │
        Slot Attention            │
             │                    │
      z_t^1 ... z_t^K             │
             │                    │
     Slot mask + Depth            │
     + Camera Geometry            │
             │                    │
             ▼                    │
     Robot-frame 3D Objects       │
      o_t^1 ... o_t^K             │
             │                    │
             ▼                    │
    Candidate Relation Tokens     │
 R_t={gripper↔obj, obj↔obj,...}    │
             │                    │
             ├──────► Gate g_t    │
             │                    │
             ▼                    │
      Cross-Attention ◄───────────┘
       Q = H_t^a
       K,V = R_t
             │
             ▼
       Recovery Adapter
             │
             ▼
           ΔH_t
             │
             ▼
   H̃_t^a = H_t^a + g_t αΔH_t
             │
             ▼
      SAME Frozen OFT Decoder
             │
             ▼
       8-step Action Chunk
```

正常：

[
g_t\approx0
\Rightarrow
\tilde H_t^a=H_t^a
]

就是原始 OFT。

失败：

[
g_t\approx1
\Rightarrow
\tilde H_t^a=H_t^a+\alpha\Delta H_t
]

Relation branch 才真正修改动作。

# 2. OFT：正常策略完全保留

定义当前输入：

[
O_t=
{I_t^m,I_t^w,L,p_t}
]

其中：

* (t)：当前决策时刻；
* (I_t^m)：主相机 RGB；
* (I_t^w)：wrist RGB；
* (L)：语言指令；
* (p_t)：proprioception。

Frozen OFT 输出：

[
\boxed{
H_t^a=\operatorname{OFT}_{enc}(O_t)
}
]

其中：

* (H_t^a)：OFT action decoder 前的 action-side hidden tokens；
* 上标 (a)：action-side representation。

原始正常动作：

[
\boxed{
A_t^N=D_{\mathrm{OFT}}(H_t^a)
}
]

其中：

* (D_{\mathrm{OFT}})：冻结的 OFT action decoder；
* (A_t^N)：normal action chunk。

# 3. Slot Attention：场景拆成实体

OFT visual tokens：

[
V_t={v_t^1,\dots,v_t^N}
]

输入 Slot Attention：

[
\boxed{
Z_t=SA_\theta(V_t)
}
]

得到：

[
Z_t=
{z_t^1,\dots,z_t^K}
]

其中：

* (N)：dense visual token 数量；
* (K)：slot 数；
* (SA_\theta)：参数为 (\theta) 的 Slot Attention；
* (z_t^i)：第 (i) 个 object slot。

同时获得对应 soft mask：

[
M_t^i(u,v)
]

其中：

* (M_t^i)：第 (i) 个 slot 在图像上的 mask；
* ((u,v))：像素坐标。

这里 Slot 只回答：

[
\boxed{\text{场景里有哪些实体？}}
]

不预先规定谁是 target、谁是 container。

# 4. 从 Slot 得到统一 Robot-frame 3D 几何

这是我建议当前主版本**直接使用 depth + camera calibration**的地方，不让网络凭 RGB 猜 3D。

利用：

[
M_t^i+\text{Depth}
]

得到该 slot 对应的 depth points。

像素反投影：

[
\boxed{
P_t^{i,C}
=========

\Pi^{-1}(M_t^i,D_t,K_C)
}
]

其中：

* (D_t)：camera depth；
* (K_C)：camera intrinsic matrix；
* (P_t^{i,C})：第 (i) 个物体在 camera frame 下的 3D points；
* (\Pi^{-1})：反投影函数。

再转换到 robot base frame：

[
\boxed{
P_t^{i,R}
=========

T_{C\rightarrow R}P_t^{i,C}
}
]

其中：

* (T_{C\rightarrow R})：camera frame 到 robot frame 的外参变换；
* (P_t^{i,R})：robot frame 下的 3D points。

得到对象中心：

[
\boxed{
p_t^i=
\operatorname{Pool}(P_t^{i,R})
}
]

其中：

* (p_t^i\in\mathbb R^3)：第 (i) 个对象在 robot frame 中的位置。

这样 camera viewpoint 改变时，最终统一到同一个 robot frame。

# 5. 每个 Object Token

定义：

[
\boxed{
o_t^i=[z_t^i;p_t^i]
}
]

其中：

* (z_t^i)：对象视觉/语义信息；
* (p_t^i)：对象 3D 几何位置；
* ([,;,])：向量拼接。

即：

[
\boxed{\text{Object = Semantic Content + Robot-frame Geometry}}
]

# 6. 构造候选 Relations

不提前判断：

> slot 2 是番茄酱、slot 5 是篮子。

而是先生成候选 relations，让语言条件化的 OFT 自己选择。

## Gripper–Object

gripper 位置来自 proprio：

[
p_t^g
]

对任意 object (i)：

[
\boxed{
\Delta p_t^{g,i}
================

p_t^i-p_t^g
}
]

以及距离：

[
\boxed{
d_t^{g,i}
=========

|\Delta p_t^{g,i}|_2
}
]

Relation token：

[
\boxed{
r_t^{g,i}
=========

\phi_g
(
[z_t^i;\Delta p_t^{g,i};d_t^{g,i}]
)
}
]

其中：

* (g)：gripper；
* (\phi_g)：小型 Relation MLP；
* (r_t^{g,i})：gripper–object relation token。

---

## Object–Object

任意两个对象：

[
\boxed{
\Delta p_t^{i,j}
================

p_t^j-p_t^i
}
]

然后：

[
\boxed{
r_t^{i,j}
=========

\phi_o
(
[z_t^i;z_t^j;\Delta p_t^{i,j}]
)
}
]

其中：

* (r_t^{i,j})：object (i) 与 object (j) 的 relation；
* (\phi_o)：object-relation MLP。

最终：

[
\boxed{
R_t=
{r_t^{g,i}}
\cup
{r_t^{i,j}}
}
]

---

# 7. Instruction 怎么告诉模型“看哪个 Relation”？

这是整个设计很重要的一点。

**不再额外训练 target/container classifier。**

因为：

[
H_t^a
]

已经来自：

[
RGB+Instruction+Proprio
]

它本身就是 language-conditioned action representation。

所以直接：

[
\boxed{
C_t=
\operatorname{CrossAttn}
(
Q=H_t^a,
K=R_t,
V=R_t
)
}
]

其中：

* (Q)：Query；
* (K)：Key；
* (V)：Value；
* (R_t)：所有 candidate relation tokens；
* (C_t)：与当前任务相关的 relational information。

例如：

> Put the ketchup into the basket.

理论上 (H_t^a) 会重点读取：

[
r^{g,ketchup}
]

和：

[
r^{ketchup,basket}
]

而忽略：

[
r^{cup,plate},r^{g,bowl},\ldots
]

所以：

[
\boxed{
\text{Relation描述世界，OFT language semantics选择当前任务相关Relation。}
}
]

---

# 8. Recovery Adapter

Relation-conditioned feature：

[
C_t
]

经过轻量 Recovery Adapter：

[
\boxed{
\Delta H_t
==========

W_oR_\rho(C_t)
}
]

其中：

* (R_\rho)：参数为 (\rho) 的 recovery adapter；
* (W_o)：投影层；
* (\Delta H_t)：对 OFT action representation 的 correction。

要求：

[
\Delta H_t,H_t^a
\in\mathbb R^{T_a\times d}
]

其中：

* (T_a)：action-side token 数；
* (d)：OFT hidden dimension。

---

# 9. Failure Gate

Relation representation 同时用于 gate：

[
\boxed{
g_t=
\sigma
\left(
G_\psi[
\operatorname{Pool}(R_t);
\operatorname{Pool}(H_t^a);
p_t
]
\right)
}
]

其中：

* (G_\psi)：Failure Gate；
* (\psi)：Gate 参数；
* (\sigma)：sigmoid；
* (g_t\in[0,1])：当前需要 recovery 的概率。

---

# 10. 最终动作

修正 hidden representation：

[
\boxed{
\tilde H_t^a
============

H_t^a
+
g_t\alpha\Delta H_t
}
]

其中：

* (\tilde H_t^a)：最终 action representation；
* (g_t)：recovery probability；
* (\alpha)：residual scale；
* (\Delta H_t)：relation-guided correction。

然后仍使用原来的 Frozen OFT decoder：

[
\boxed{
\hat A_t=
D_{\mathrm{OFT}}(\tilde H_t^a)
}
]

# 12. 训练数据只需要两大类

## A. Normal Data

原 LIBERO demonstration + OFT 正常 rollout：

[
\boxed{
D_N=
{O_t,A_t,g_t^\star=0}
}
]

其中：

* (D_N)：normal dataset；
* (A_t)：正常 action；
* (g_t^\star=0)：不需要 recovery。

主要用于：

[
\mathcal L_{\mathrm{gate}}
]

中的 negative samples。

---

## B. Failure-Recovery Data

在 **training perturbation** 环境中运行 frozen OFT：

```text
OFT rollout
    ↓
failure
    ↓
save simulator state
    ↓
teacher / FSM recovery
    ↓
successful recovery trajectory
    ↓
handoff back to OFT
```

得到：

[
\boxed{
D_R=
{
O_t,
A_t^{R\star},
g_t^\star
}
}
]

其中：

* (D_R)：recovery dataset；
* (A_t^{R\star})：成功 teacher recovery action；
* (g_t^\star=1)：处于 recovery segment。

# 13. Recovery Action 监督

预测：

[
\hat A_t=
[
\hat a_{t,1},\ldots,\hat a_{t,H}
]
]

teacher：

[
A_t^{R\star}
============

[
a_{t,1}^{R\star},\ldots,a_{t,H}^{R\star}
]
]

其中：

* (H=8)：action chunk 长度；
* (h)：chunk 内第 (h) 个动作。

使用：

[
\boxed{
\mathcal L_{\mathrm{rec}}
=========================

\frac1H
\sum_{h=1}^{H}
|
\hat a_{t,h}
------------

a_{t,h}^{R\star}
|_1
}
]

这条 loss 直接反向传播：

```text
Action loss
   ↓
Frozen decoder
   ↓
Recovery Adapter
   ↓
Cross-Attention
   ↓
Relation Encoder
   ↓
Slot Attention
```

所以 Relation **不需要单独定义 relation label**。

它会直接学习：

> 哪种关系对 corrective action 有用。

---

# 14. Gate 监督

真实 label：

[
g_t^\star\in{0,1}
]

训练：

[
\boxed{
\mathcal L_{\mathrm{gate}}
==========================

\operatorname{BCE}
(
g_t,g_t^\star
)
}
]

其中：

* (g_t)：模型输出；
* (g_t^\star)：normal/recovery segment 标签；
* BCE：binary cross entropy。

---

# 15. Slot 是否需要额外监督？

这是唯一我建议保留一点辅助监督的地方。

因为纯 action loss 不一定保证 Slot Attention 分出稳定对象。

在 LIBERO 仿真里可以利用 simulator segmentation / object mask，训练 Slot object decomposition。

例如：

[
\boxed{
\mathcal L_{\mathrm{slot}}
==========================

\operatorname{MaskLoss}
(
M_t,M_t^\star
)
}
]

其中：

* (M_t)：Slot Attention 预测 masks；
* (M_t^\star)：simulator 提供的 object masks。

这是**训练期 privileged supervision**。

推理时不需要 simulator segmentation。

如果已有稳定的 SlotAttention checkpoint，也可以直接初始化，然后弱化这项 loss。

[
\boxed{
\mathcal L
==========

\lambda_r\mathcal L_{\mathrm{rec}}
+
\lambda_g\mathcal L_{\mathrm{gate}}
+
\lambda_s\mathcal L_{\mathrm{slot}}
}

* (\mathcal L)：总训练 loss；

* (\lambda_r,\lambda_g,\lambda_s)：三个 loss 权重。

# 18. 论文真正的核心故事

不是：

> 我们提出了一个新的 relation VLA。

而是：

[
\boxed{
\textbf{Relational Recovery as a Post-hoc Interface for Frozen VLAs}
}
]

Normal VLA 已经知道：

[
\boxed{\text{What should I do?}}
]

Slot 提供：

[
\boxed{\text{What entities are present?}}
]

Robot-frame geometry 提供：

[
\boxed{\text{Where are they?}}
]

Relation 表示：

[
\boxed{\text{How are task-relevant entities spatially related?}}
]

语言条件化的 OFT feature 负责：

[
\boxed{\text{Which relation matters for this task?}}
]

Recovery Adapter 最后解决：

[
\boxed{\text{How should the nominal action be corrected?}}
]

最终就是：

[
\boxed{
\text{Entities}
\rightarrow
\text{3D Relations}
\rightarrow
\text{Task-conditioned Retrieval}
\rightarrow
\text{Corrective Residual}
}
]

# 19. 后面必须做的核心 ablation

为了面对 SlotVLA 等工作的质疑，我认为至少四个：

[
\boxed{\text{Global Recovery}}
]

只用 OFT global feature。

[
\boxed{\text{Slot Recovery}}
]

用 current object slots。

[
\boxed{\text{2D Relation Recovery}}
]

用 image-plane relations。

[
\boxed{\text{3D Relation Recovery — Ours}}
]

用 robot-frame relations。

再加：

[
\boxed{\text{Always-on Relation vs Gated Relation}}
]

回答：

> 为什么不把我们的 relation branch 一直用于正常动作？

这五个实验基本就决定这个方法的故事能不能成立。

**最终我们不是要证明“Relation 能做机器人操作”——这个别人已经证明过；我们要证明的是：显式、任务条件化的 robot-centric relations，是给已有强 VLA 增加失败恢复能力的一种有效且不破坏 nominal policy 的 corrective interface。**
