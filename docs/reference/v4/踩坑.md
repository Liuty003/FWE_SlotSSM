# V4 实验踩坑记录

## `ModuleNotFoundError: No module named 'imageio.v2'`

### 原因

仓库机器上同时存在多个 Python：

- `/home/liutianyu/anaconda3/bin/python` 是 base 环境，其中 `imageio==2.9.0`，没有当前代码使用的 `imageio.v2`；
- `/data/lty/code/naive-e-slotssm/.conda/envs/openvla-oft/bin/python` 是 OpenVLA-OFT/LIBERO 环境，其中 `imageio==2.37.2`，并且包含匹配的 PyTorch、TensorFlow、Transformers、LIBERO 和 robosuite 依赖。

因此，问题不是代码里忘记安装依赖，而是 shell 中裸写 `python` 时调用了 base Python。不要为了消除报错而随意升级 base 环境；这可能破坏其他项目，而且仍不能保证 LIBERO/OpenVLA 的整套依赖一致。

### 标准解决方法

OFT/LIBERO 的在线 rollout、teacher 采集、handoff 审计统一使用：

```bash
/data/lty/code/naive-e-slotssm/.conda/envs/openvla-oft/bin/python
```

归还审计不要直接执行 Python 文件，统一通过带运行时检查的包装脚本：

```bash
scripts/run_relational_oft_handoff_audit.sh \
  --teacher-root /path/to/teachers \
  --output-root /path/to/audits \
  --task-suite libero_10 \
  --normalization-key libero_object \
  --candidate-phase release_target \
  --gpu 1
```

包装脚本会：

1. 默认选择仓库内的 `openvla-oft` Python；
2. 在正式加载 7B 模型前检查 `imageio.v2` 和 imageio 版本；
3. 检查通过后才启动 `audit_relational_oft_handoffs.py`；
4. 找不到环境时立即给出明确错误，而不是等到模型任务中途失败。

其他 OFT/LIBERO 脚本统一用通用启动器：

```bash
scripts/run_openvla_oft_python.sh scripts/某个脚本.py --参数 ...
```

专用的 handoff 启动器内部也是调用这个通用启动器，运行时检查只有一份实现。

如环境搬迁，可显式覆盖：

```bash
OFT_PYTHON=/absolute/path/to/python \
  scripts/run_relational_oft_handoff_audit.sh --help
```

### 快速诊断

```bash
which python
python -c 'import sys, imageio; print(sys.executable, imageio.__version__)'
/data/lty/code/naive-e-slotssm/.conda/envs/openvla-oft/bin/python \
  -c 'import sys, imageio, imageio.v2; print(sys.executable, imageio.__version__)'
```

预期最后一条输出仓库内 `openvla-oft/bin/python` 和 `imageio 2.37.2`。

### tmux 与批量任务

tmux 不会自动继承另一个终端里执行过的 `conda activate`。因此 tmux 命令和批量脚本中也必须使用包装脚本或 Python 的绝对路径，不能假设当前环境已经激活。例如：

```bash
tmux new-session -d -s handoff_audit \
  "cd /data/lty/code/naive-e-slotssm && \
   scripts/run_relational_oft_handoff_audit.sh ... 2>&1 | tee /path/to/run.log"
```

### 适用边界

- 仅处理 safetensors 的轻量训练或离线统计可以使用普通 Python，只要依赖检查通过；
- 任何需要 OpenVLA-OFT、LIBERO、MuJoCo、robosuite、TensorFlow 图像预处理或 MP4 输出的任务，固定使用 `openvla-oft` 环境；
- `cuDNN/cuFFT/cuBLAS factory already registered` 通常是 TensorFlow 与 PyTorch 同进程加载时的非致命提示，不等同于 `imageio.v2` 缺失。
