# V4.4.2：短桥恢复、双控制权估计与单步闭环动作

本文是对 [v4_4.md](./v4_4.md) 的修正版执行方案。它继承 V4.3 的关系恢复主线，但根据 Mug/Pudding、Black Bowl 的闭环结果和完整 LIBERO-Plus 10,030 条实验约束，修正以下关键问题：

1. 不使用同一个 `V_OFT(s)` 同时决定接管和归还；
2. recovery action 从 `8×7` 长 chunk 改成优先预测 `1×7` 的局部闭环动作；
3. teacher 数据截断到最早经过 OFT 续跑认证的 resumable state；
4. FSM 和 target localization 暂时保留为 teacher、可靠上界、fallback 和消融项，不在没有证据时直接删除；
5. 正式主实验推理时只使用各 backbone 原本拥有的输入，RGB-D、分割、contact 和 simulator state 只用于训练监督与离线认证。

当前 V4.4.2 是下一阶段计划，不应把尚未训练的结构写成已经取得的结果。

## 一、我们要解决的问题

恢复模块不负责重新完成整个任务，而只负责构造一条尽可能短的 bridge：

```text
基础策略进入局部失效状态
          ↓
recovery 执行少量纠偏动作
          ↓
到达基础策略可以重新完成任务的状态
          ↓
归还冻结基础策略
```

形式化地写成：

\[
x_f \xrightarrow{\pi_R} x_{\mathrm{resume}}
\xrightarrow{\pi_B} \mathrm{success},
\]

其中：

- \(\pi_B\) 是冻结的 OpenVLA-OFT、DP、ACT 等基础策略；
- \(x_f\) 是局部失效或即将产生不可逆错误的状态；
- \(\pi_R\) 是恢复策略；
- \(x_{\mathrm{resume}}\) 是经过基础策略反事实续跑认证的可归还状态。

“最短 bridge”首先指同一条有效 teacher 路径上最早的 resumable state，不宣称求得整个状态空间中的全局最短路径。

## 二、为什么不能用一个 `V_OFT(s)` 同时接管和归还

定义：

\[
V_{\mathrm{OFT}}(s)
=P(\pi_{\mathrm{OFT}}\text{ 从 }s\text{ 重新规划后最终成功}).
\]

它适合判断 recovery 后能否归还 OFT，但不适合直接判断何时开始接管。

在基本确定性的固定失败轨迹上，如果 OFT 从初始状态最终就会失败，那么沿这条轨迹很早的状态也可能全部满足：

\[
V_{\mathrm{OFT}}(s_0)=V_{\mathrm{OFT}}(s_1)=\cdots=0.
\]

若用这个值触发接管，模型会从第 0 步开始 recovery，而不是等到真正的局部失败边界。Black Bowl 已经观察到过早接管会因为几何预测误差停在 approach。

因此 V4.4.2 使用两个语义不同但共享 encoder 的估计头：

1. `enter-risk head`：未来短时内是否会出现失败、停滞、错误接触或不可逆退化，用于决定何时接管；
2. `resume-value head`：从当前状态重新规划后，冻结基础策略是否能最终完成任务，用于决定何时归还。

未来可以研究统一的切换优势：

\[
A_{\mathrm{switch}}(s)
=Q_R(s)-Q_B(s)-c_{\mathrm{intervention}},
\]

但它依赖已经成熟的 recovery policy，不作为第一版监督目标。

## 三、V4.4.2 模型结构

```text
backbone 原生观测 + language/proprio + nominal action
                         ↓
              shared recovery encoder
                         ↓
       task-conditioned recovery representation z_t
          ┌──────────┬──────────┬──────────┬───────────┐
          ↓          ↓          ↓          ↓           ↓
    enter-risk   resume-value  skill/router  auxiliary  local action
       head          head         head        heads      1×7 / 2×7
          │            │                                  │
          └──────── ownership hysteresis/latch ───────────┘
```

### 3.1 共享表征

对于 OpenVLA-OFT 版本，延续 V4.3 的基本思路：

```text
OFT visual tokens
    ↓ object/slot representation
candidate relations
    ↓ OFT action query cross-attention
task-conditioned relational context C_t
    ↓ 与 nominal action/query 表征汇合
shared recovery representation z_t
```

`enter-risk`、`resume-value`、辅助目标和 local action 从同一上游表征分叉。共享表示不意味着 simulator truth 会成为在线输入；privileged 信息只提供训练标签。

### 3.2 跨 backbone 适配

DP、ACT 和 OFT 使用各自的 native-input adapter：

```text
OFT native observation ─┐
DP native observation  ─┼─> backbone adapter ─> shared recovery interface
ACT native observation ─┘
```

各 backbone 的视觉编码、状态输入、action space 和 chunk 定义可以不同，但保持以下语义一致：

- `enter-risk` 表示是否应该干预；
- `resume-value` 表示能否归还；
- router 表示局部失败/恢复技能；
- recovery action 只执行局部纠偏；
- 正常状态严格 bypass recovery action。

## 四、单步局部恢复动作

当前 V4.3 一次预测：

\[
\hat A_t\in\mathbb R^{8\times7},
\]

并执行其中多个动作后再观察。它容易跨越 approach、descend、close、lift 等控制边界，也无法及时响应接触和目标位移。

V4.4.2 第一版改为：

\[
(z_t,a_t^B)\rightarrow \hat a_t^R\in\mathbb R^7,
\]

每次只执行一个恢复动作，然后重新获取观测。`2×7` 只作为效率消融，不作为默认版本。

连续动作维度必须显式限幅：

\[
\|\Delta p_t\|\le d_{\max},\qquad
\|\Delta R_t\|\le r_{\max}.
\]

需要比较两种参数化：

1. 直接输出 bounded local action；
2. 输出相对 nominal action 的 bounded residual。

当 nominal action 已经明显错误时，纯 residual 可能受到错误动作牵制，因此默认先测试直接局部动作。

## 五、控制权与部署逻辑

部署时维护显式 ownership 状态和迟滞：

```text
NORMAL:
    enter-risk 连续 N_enter 次超过阈值
        → 切换到 RECOVERY
    否则
        → 原样执行基础策略动作

RECOVERY:
    resume-value 连续 N_exit 次超过阈值
        → 清空基础策略旧 action chunk
        → 从当前观测重新规划
        → 切换到 NORMAL
    否则
        → 执行一个 bounded local recovery action
```

必须保留：

- enter/exit 不同阈值；
- 连续确认；
- minimum recovery steps；
- maximum recovery horizon；
- handoff 后 cooldown；
- NORMAL 时基础策略 exact bypass。

`resume-value` 和 `enter-risk` 可以共享 encoder，但不能因为其中一个 head 校准而改变另一个 head 的决策边界。

## 六、反事实 branch 的严格定义

从轨迹中间状态测试基础策略时要区分：

1. `continue-current-chunk`：保留原 action chunk id/offset，继续执行旧 chunk；
2. `fresh-replan`：丢弃旧 chunk，从当前观测重新调用基础策略。

用途如下：

- handoff/resume 标签使用 `fresh-replan`，因为真实归还时也会重新规划；
- enter-risk/failure-onset 分析需要同时保存实际 chunk offset，判断当前正在执行的动作是否已经导致失效；
- 所有 branch 必须恢复对应 MuJoCo state、controller state、相机状态和随机数状态。

`oft_archival_rollout_v4` 已保存真实 chunk id/offset、状态和 RNG，可支持该协议。

## 七、最短 bridge 数据构造

对每条 simulator-verified teacher recovery 轨迹：

```text
s_0 --teacher--> s_1 --teacher--> ... --teacher--> s_T
```

从候选状态运行 frozen backbone 的 `fresh-replan` 续跑，寻找：

\[
t^*=\min_t\{t:\pi_B\text{ 从 }s_t\text{ 开始完成任务}\}.
\]

只保留：

\[
(s_0,a_0^*),\ldots,(s_{t^*-1},a_{t^*-1}^*).
\]

并生成：

- \(s_0\ldots s_{t^*-1}\)：`resume=0`；
- \(s_{t^*}\)：`resume=1`；
- \(t^*\) 之后的 teacher action：不进入 recovery action 正样本；
- 无法找到认证 handoff 的分支：继续 teacher、换技能或作为 verifier 负样本，不能伪造正标签。

为了控制 10,030 条上的成本，先稀疏 branch，再在首次成功区间做 coarse-to-fine 搜索，不需要对每一个相邻环境步完整续跑。

## 八、enter-risk 标签

不能把“该 episode 最终失败”复制到整条前缀。enter-risk 应围绕局部干预时机生成，候选证据包括：

- 未来短窗口内 BDDL 进度回退或长时间不增长；
- 空抓、掉落、错误接触、碰撞或目标向错误方向移动；
- fixture joint 长时间无有效变化；
- nominal action 与 verified corrective action 显著冲突；
- 状态已经进入不可恢复区域；
- 自动 miner 的 failure onset 及其置信区间。

建议标签语义：

```text
远离 failure onset 的正常前缀       → KEEP_BASE
短期内仍稳定推进                    → KEEP_BASE
failure onset 邻域且 recovery 可用  → ENTER_RECOVERY
低置信边界                          → UNKNOWN / 降权
```

正常成功轨迹必须作为负样本，专门约束 false takeover。

## 九、辅助监督

训练期可以继续使用：

- target-relative geometry / depth prediction；
- target mask、slot consistency 或 relation selection；
- contact、grasp quality、attached state；
- phase/subgoal progress；
- fixture joint state；
- recovery completion 和 OFT resumability。

这些 head 用于塑造共享表征，默认不直接硬控制动作或夹爪。

### 9.1 Relation attention 监督

可以增加 attention-level geometry 监督，但暂时不删除已有 target-delta head。若目标实例覆盖多个 patch/slot，应使用由训练期 segmentation 生成的软目标，而不是强迫唯一 slot：

\[
L_{\mathrm{relation}}
=KL(\alpha\|\alpha^*_{\mathrm{target-overlap}}).
\]

也可以令：

\[
\widehat{\Delta p}=\sum_i\alpha_i\Delta p_i,
\qquad
L_{\mathrm{geometry}}=
\|\widehat{\Delta p}-\Delta p^*\|.
\]

通过消融比较：

- target-delta head；
- relation-attention supervision；
- 两者同时使用；
- 不使用 geometry auxiliary。

## 十、Recovery loss

第一版损失：

\[
L_R=
L_{\mathrm{action}}
+\lambda_d L_{\mathrm{direction}}
+\lambda_b L_{\mathrm{bound}}
+\lambda_s L_{\mathrm{smooth}}
+\lambda_{aux}L_{\mathrm{aux}}.
\]

其中：

- `action`：单步 teacher action 的 L1/Huber；
- `direction`：approach、escape 等适用状态下的动作方向一致性；
- `bound`：只惩罚超过局部安全限幅的动作；
- `smooth`：只作用于连续位姿维度，并在真实阶段切换处降权；
- `aux`：geometry、relation、contact、phase、resume 等训练期辅助目标。

不默认使用无条件的：

\[
L_{\mathrm{mag}}=\|\hat a_t\|^2,
\]

因为当前模型已经存在动作过小、停顿和超时问题。夹爪维度也不做普通 smoothness，以免明确的 open/close 被平均成中间值。

## 十一、Handoff-aware DAgger

```text
student 闭环进入跑偏状态
        ↓
保存精确 snapshot、chunk offset 和原生观测
        ↓
privileged teacher 生成纠偏
        ↓
沿 teacher 分支 coarse-to-fine 运行 frozen backbone
        ↓
找到 earliest certified handoff
        ↓
只加入 handoff 前动作以及 resume/ownership 标签
```

只保留经过物理验证的 teacher 正样本。失败 teacher 分支可以作为 candidate scorer、resume verifier 或 failure classifier 的负样本，但不能进入 action 正样本。

DAgger 优先覆盖：

- 过早闭夹；
- 目标被推偏后继续执行旧动作；
- 空中抽搐；
- 接近目标但停滞；
- 抓住后掉落；
- 碰撞后未后撤；
- handoff 后基础策略再次立即失败；
- recovery 超时。

## 十二、多模态动作的第二阶段方案

若单步 closed-loop 仍出现明显平均化，再引入 `K=4` 的 candidate action head：

\[
z_t\rightarrow\{a_t^{(1)},\ldots,a_t^{(K)}\}.
\]

单纯 best-of-K BC 不能可靠训练推理选择器。优先使用精确 snapshot 短分支评估候选动作的：

- 接近/脱困进展；
- 接触和碰撞；
- BDDL/fixture progress；
- handoff readiness；
- 后续 resumability。

再训练 candidate effect scorer 选择候选。只有在单步单峰 head 确认失败后才进入这一阶段，暂不上 Diffusion/Flow。

## 十三、FSM 和 target localization 的定位

Black Bowl 的 31/44 来自：

```text
learned gate
+ learned target delta
+ deterministic grasp FSM
+ frozen OFT
```

因此新版本中 FSM 暂时保留为：

- privileged/structured teacher；
- learned action 的性能上界；
- 必要时的安全 fallback；
- 结构消融基线。

只有单步 learned recovery 在同一闭环任务上达到或超过 FSM，才能从主方法中删除 FSM。70.5% 不得写成纯 neural action head 的结果。

## 十四、公平输入协议

正式 matched-input 主实验中，hybrid 推理只能使用对应 backbone 的原生输入和 nominal action。对于原本只使用 RGB/proprio/language 的 backbone，以下信息禁止作为在线输入：

- simulator depth truth；
- instance segmentation；
- object/fixture pose；
- contact truth；
- BDDL predicate truth；
- MuJoCo state；
- oracle phase、target name 或 failure type。

它们可以用于：

- teacher；
- failure/phase/resume 标签；
- auxiliary supervision；
- candidate branch 评价；
- 训练期蒸馏；
- 离线审计。

历史 V4.3/Black Bowl 在线 RGB-D 版本保留为 RGB-D hybrid 结果，不能与严格 native-input 主表混写。

## 十五、训练顺序

1. 完成并校验 10,030 条基础策略 archival baseline。
2. 自动挖掘 failure onset、failure type 和低置信案例。
3. 对代表性失败建立少量通用 teacher skill library。
4. 从精确 snapshot 运行 verified teacher。
5. coarse-to-fine 搜索 earliest OFT-resumable state，并截断 teacher。
6. 构造 `KEEP_BASE / ENTER_RECOVERY` 数据和独立 resume-value 数据。
7. 保持现有 encoder 不变，先训练 `1×7` local action head。
8. 训练/校准 enter-risk 和 resume-value 两个 head。
9. 加入 relation/geometry/contact/phase 等训练期辅助监督。
10. 小规模闭环 smoke，保存所有 student 偏离状态。
11. 运行 handoff-aware DAgger。
12. 全量 hybrid 评测并统计 repaired、regressed、false takeover 和 handoff success。
13. 若单步 action 仍多模态平均，再测试 candidate head/effect scorer。
14. 固化 OpenVLA-OFT 版本后再实现 DP、ACT native adapter。

## 十六、最小消融顺序

不要同时修改所有组件。按以下顺序判断因果：

| 实验 | 唯一主要变化 | 要回答的问题 |
|---|---|---|
| A | 当前 `8×7` learned action | 神经恢复基线是多少 |
| B | `8×7 → 1×7` | 长 action horizon 是否是主要瓶颈 |
| C | B + earliest-resume 截断 | 无关后半程 teacher 是否污染动作学习 |
| D | C + 独立 resume-value head | 学习 handoff 是否优于固定时长 |
| E | D + handoff-aware DAgger | 闭环分布偏移能否被修复 |
| F | E + candidate/effect scorer | 剩余失败是否主要来自多模态平均 |
| G | learned geometry + FSM | 当前可靠混合上界 |

每一项都必须使用相同任务、初态、最大环境步数和基础策略 checkpoint。

## 十七、核心评测指标

- baseline success rate；
- hybrid success rate；
- baseline failures repaired；
- baseline successes regressed；
- net success gain；
- enter-risk precision/recall 和 false takeover；
- resume-value accuracy/calibration；
- handoff 后最终成功率；
- handoff 后短期重新接管率；
- recovery 平均步数、超时率；
- cumulative EE displacement；
- 空抓、掉落、碰撞、停滞等分类型恢复率；
- 按 suite、官方扰动、difficulty、failure type 分层结果。

当前允许训练和评测使用相同的 10,030 个固定实例，因此主结果属于 closed-set/in-sample repair，不表述为未见任务或未见初态泛化。

## 十八、最终决策摘要

V4.4.2 确定采纳：

- recovery 是通向 frozen backbone competence region 的短 bridge；
- teacher 截断到 earliest certified handoff；
- 单步闭环 local action；
- handoff-aware DAgger；
- relation/geometry/direction 辅助监督；
- 正常状态 exact bypass；
- matched-input、公平的跨 backbone 协议。

V4.4.2 修正：

- 接管和归还使用两个共享 encoder、语义不同的 head；
- branch 明确区分 continue-current-chunk 与 fresh-replan；
- 不使用会鼓励停顿的无条件 action magnitude penalty；
- smoothness 不作用于夹爪切换，也不能压平阶段边界。

暂不采纳：

- 立即删除 FSM；
- 立即删除 target-delta；
- 用单一 `V_OFT(s)` 同时控制 enter/exit；
- 未验证单步 head 前直接上 Diffusion/Flow；
- 没有候选效果监督时直接依赖 best-of-K confidence；
- 在正式推理中使用基础策略原本没有的 RGB-D 或 simulator truth。

V4.4.2 的第一项模型实验应当是：保持 V4.3 encoder 和训练数据尽量不变，只把 `8×7、执行4步` 改成 `1×7、执行1步`，用同一批闭环失败实例判断 action horizon 是否确实是当前 learned recovery 的主要瓶颈。

## 十九、实施记录（2026-08-27）

第一项最小实验已经开始实施：

- 已将 OFT 输入的 56 个 action-query token 与 recovery 输出 horizon 解耦；
- 旧 V4.3 checkpoint 默认仍输出 `8×7`，保持兼容；
- 新模型种类为 `v44_local_closed_loop_recovery_v1`，输出 `1×7`；
- online runner 对单步模型最多只入队一个动作，下一环境步必须重新观察；
- 已有 15 个 V4/V4.3/V4.4 相关测试通过；
- 审计后已修复短 horizon 初始化：完整继承 relation encoder、gate、LayerNorm 和
  action MLP 隐层，只将旧输出层的前 7 行复制为新首动作；初始化时新模型与旧模型
  的 first action 数值一致。
- 特征契约已将 OFT 原生 `8×7` 上下文与 recovery target horizon 解耦；V4.4.2
  使用 `recovery_sampling_stride=1`、`recovery_target_horizon=1`。
- 新 online runner 对平移和旋转分别施加显式 L2 局部限幅，并在报告中记录是否裁剪。

下面是修复前第一次尝试的历史数值，**已被代码审计判定为无效消融，不作为实验结论**。
原因是当时短 horizon 加载逻辑错误地重置了整个 `direct_action` MLP，而不是只截取旧
输出层的 first-action 行；同时数据观测间隔仍为 4/8 步而非严格逐步状态：

```text
旧 V4.3 8-step head 的 first-action MAE：0.028979
新 V4.4.2 1-step head 的 action MAE：    0.029698
相对变化：                              +2.48%
```

因此不能从上述 MAE 判断单步 head 是否有效。修复后的必要实验是先用 stride-1、
single-target 特征重新训练，再使用相同 gate 和恢复时长，对同一批 Black Bowl 失败状态运行：

1. 旧 `8×7、执行4步` learned action；
