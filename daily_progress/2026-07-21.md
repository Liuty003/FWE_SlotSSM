## 4. 今日遇到的问题及处理

### 4.1 Triton/Mamba 设备一致性

此前 Mamba2 曾因 CPU/GPU tensor 混用出现：

```text
Pointer argument cannot be accessed from Triton (cpu tensor?)
```

在线 wrapper 将 Slot/Mamba 紧凑模块固定在同一 CUDA device，当前未再出现该问题。

### 4.2 Stage-1 checkpoint 的 `missing=982`

这是因为 Stage-1 文件只保存 Slot 相关 adapter/head，而 wrapper 同时包含冻结的完整 OpenVLA；使用 `strict=False` 加载时，未包含的基础模型参数被报告为 missing。基础 OpenVLA 已从原 checkpoint 加载，因此不是 982 个 Slot 权重缺失，也不是当前错误。

### 4.3 Stage-3 在线动作塌缩

离线 L1 并不能保证闭环控制有效。完整 episode 揭示连续动作头输出接近数据均值，缺少足够的状态相关变化。可能原因包括：

- 单层连续回归头容易优化到均值；
- Stage-3 训练数据和在线 `libero_spatial` 分布不完全一致；
- 在线没有 oracle object-stage cue；
- 离线消融已经显示 Stage-3 对 predicted-next slot 利用很弱；
- 训练目标和闭环 action distribution 存在 exposure bias。

当前处理：Failure-Aware 主线暂用成功的原始 OpenVLA，Stage-3 作为独立待修问题。

### 4.4 Predictor 忽略 action/proprio

成功示范中动作几乎由状态决定。给定视觉状态后，网络无需使用 action 也可以降低 next-slot loss，所以简单拼接 action 并不能保证学到动作后果。

当前处理：引入同状态、多动作、不同后果的仿真干预数据，并计划增加 matched counterfactual/ranking loss。

### 4.5 MuJoCo state 不包含 observable buffer

最初在同一个环境中保存/恢复 flat state。物理 state 相同，但恢复后的图像与 `env.step()` 刚返回的图像哈希不同，并且恢复操作改变了后续主策略闭环。

当前处理：改为双环境；主环境不恢复，分支环境使用统一的规范恢复观测。所有 matched branch 的恢复图像都通过哈希一致性检查。

### 4.6 robosuite episode counter 不属于 simulator flat state

恢复 MuJoCo state 不会自动恢复 `timestep` 和 `done`。大量分支执行可能错误触发 episode horizon。

当前处理：每条独立分支显式重置分支环境的 `timestep=0`、`done=False`；主环境区分 `check_success()` 和 horizon `done`。

### 4.7 `/data2` 新顶层目录权限不足

尝试创建 `/data2/lty/failure-aware-slotssm` 时没有权限。没有使用 sudo，而是继续使用已经可写的：

```text
/data2/lty/naive-e-slotssm-runs/
```

## 5. 当前仍存在的问题和风险

1. 当前 action-conditioned predictor 没有通过动作敏感性验收。
2. 首批反事实数据只有一个任务、一个 episode、20 个独立 state，规模不足。
3. 当前干预是重复执行同一个动作 4 步，不完全等价于真实 VLA 产生的 4-step action chunk。
4. 夹爪和旋转干预在某些阶段造成的视觉差异仍小于平移干预。
5. 反事实数据目前以 JSONL、PNG、NPZ 保存，尚未转换成高吞吐训练数据格式。
6. 尚未对 before/after 图像批量提取并缓存 Stage-1 slots；直接训练会重复运行 7B vision backbone。
7. Failure label 和 failure onset 还没有正式定义；当前只有动作干预及后果，不应简单把所有 perturbation 都标为 failure。
8. 当前在线 SlotSSM 每步重算 32 帧，速度较慢，真正 recurrent cache/reset 仍未实现。
9. Stage-3 动作塌缩尚未修复，因此 Embodied-SlotSSM 完整成功率复现还没有完成。
10. 原始 OpenVLA baseline 使用 `trust_remote_code=True` 时可能更新远端 Python 文件，后续需要固定为仓库内实现或固定 revision，保证可复现性。

### 近期第 2 步：预计算反事实 Slot 数据集

建立转换脚本：

```text
PNG/JSONL
  → frozen Stage-1 slot extraction
  → before slots / step-wise after slots
  → normalized executed action / robot state
  → compact safetensors 或 shard 数据集
```

同时保存对象真值变化，用于诊断 Slot deviation 是否对应真实对象变化。

### 近期第 3 步：重训因果 action-conditioned predictor

训练需要同时包含：

- 原始 LIBERO-Mem demonstration transition loss；
- matched branch outcome loss；
- 同状态错误动作的 counterfactual/ranking loss；
- action/proprio shuffle sensitivity regularization；
- nominal 与 perturbation 的 pairwise outcome separation。

验收不能只看 next-slot L1，还必须要求：

- 正确 action 的预测优于打乱 action；
- 正确 action 的预测优于同状态错误 action；
- action 改变时预测 outcome 有稳定、方向合理的变化；
- 在 held-out fork state 和 held-out task 上成立。

### 之后：Failure Detector 和恢复

只有 predictor 通过上述验收后，才进入：

1. 定义 post-transition deviation features；
2. 从干预 rollout 中标注真实 failure onset；
3. 训练 post-transition Failure Detector；
4. 做阈值、AUROC、F1、误触发率和提前量评测；
5. 检测失败后使用短视野闭环 OpenVLA 重规划；
6. 最后才考虑候选动作 risk/ranking。

## 8. 今日结论

今天最重要的成果不是单纯多训练了一个模型，而是通过完整在线 A/B、动作打乱消融和严格仿真分叉，排除了两个容易产生错误结论的路径：

1. 离线 loss 正常不等于 Stage-3 能在线控制机器人；
2. 拼接 action 输入且 next-slot loss 下降不等于模型真正学会动作后果。

当前已经有一条可工作的正常 OpenVLA 策略、完整在线日志协议，以及严格同状态多动作的反事实数据生成能力。下一阶段的核心是扩大干预数据，并把 predictor 从视觉相关性修正器训练成真正对执行动作敏感的对象 transition model。

结论：模型改善了共同状态演化，但动作差异仍被绝对状态预测误差淹没，严格验收失败。

### 9.4 Differential effect predictor 使用动作但跨任务泛化失败

新增：

```text
scripts/train_counterfactual_effect_predictor.py
scripts/evaluate_counterfactual_effect_predictor.py
```

目标改为：

```text
executed_action - nominal_action
    → branch_after_slots - nominal_after_slots
```

这样 matched pair 会消去共同视觉演化。模型在 task 8 验证集上表现出约 10% 的 shuffle degradation 和约 0.30 的 delta cosine，证明相比上一版已经开始使用动作。但最佳 checkpoint 在完全留出的 task 9 上：

- zero-effect MAE：0.03781；
- predicted-effect MAE：0.04300，比零基线差 13.7%；
- shuffled-effect MAE：0.04518，较正确动作差 5.1%；
- branch retrieval：10%，等于随机；
- correct-vs-shifted win rate：51.5%；
- branch delta cosine：0.074。

结论：问题已经从“完全忽略动作”推进到“确实使用动作，但 action→Slot effect 映射过拟合训练任务，无法可靠泛化”。当前每个任务只有约 20 个 fork state，不能通过增加训练步数解决；5000-step 训练后期已经明显过拟合，最佳验证点出现在 step 400。

### 9.5 更新后的下一步

在训练 Failure Detector 前，需要：

1. 扩大每个 task 的 episode 数，优先采 episode 1～4，使每个任务从约 20 个 state 增加到约 100 个 state；
2. 采用按 episode 留出而不是只按 task 留出，分别评估同任务新状态泛化与跨任务泛化；
3. 分析 Stage-1 Slot 对 1 cm 级机器人/物体变化的信噪比，区分机器人运动 Slot 与任务物体 Slot；
4. 训练时对 branch effect 按真实 effect magnitude 分层或加权，避免大量接近零的对象变化主导；
5. 把 object privileged state 仅用于评测/采样加权，不能作为策略输入；
6. 只有 effect predictor 同时击败 zero-effect baseline、shuffle 明显退化且 retrieval 高于随机后，才进入 Failure Detector。
